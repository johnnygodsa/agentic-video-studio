# 流程:director 全流程、卡點、開工提問、派工、機器、多支片

開工、卡點、派工、跑指令前讀。門檻與順序在程式(`pipeline\gates\`、`director.py`),這裡只寫主對話要做的事;規格 `pipeline\docs\director.md`、`director_ab.md`、`gates_inventory.md`。頻道檔優先於本檔。

## 1. director 跑全流程,主對話三接觸點
使用者只出現三次:開工提問(§3)、C 段選配音後端(§6)、E 排程後的否決窗(4_交付發片 §1)。沒有樣片、沒有聽審、沒有 v1 審。
1. **開工**:沒指定題先開選題會議(1_選題 §10)→ 開工提問(§3)→ `python -X utf8 pipeline\director.py brief <tag> --topic "…" --angle "…" --channel <頻道> --format <片型> [--publish …] [--url …] --flow v3`(片型鍵見 `gates\specs.py`;`--flow v3` = 2026-11-03 省 token 流程,新片一律加;brief 沒有 flow 的舊片走 v2 原路徑,一支片內不切)→ 背景跑 `python -X utf8 pipeline\director.py run <tag> --from A --to D --ver v1 --title <片名> --channel <頻道>`。
2. **C 段選後端**:run 停在卡點 `待選後端` → 問使用者(§6)→ `run <tag> --from C --to D --ver v1 --backend <local|kaggle|colab> …`。
3. **E 否決窗**:程式看不到的事主對話做:唸法清單 `decide_<ver>.md` 由 director C 段 `唸法決定` 步決定並登錄、主對話只在它卡點時接手(3_製作 §5)、look 清單與 QA 圖(3_製作 §8)、標題封面與說明檔(4_交付發片 §3–§6)→ `run <tag> --from E --to E --ver v1 --title … --channel … [--publish-at …] [--cover …]` → 否決窗訊息(4_交付發片 §1)。
- 段序 A 資料 → B 文案 → B4 配音稿 → C 配音 → D 畫面 → E 自審上片;gate 全過才進下一段,不回頭重做。`director.py --explain <段>` 印 gate 項目,`status <tag>` 看各段狀態。
- 結案不需口令:公開 24h 看留言(2_文案 §5)→ 72h 回填(4_交付發片 §7)→ 清理(§8),下一支片開工時順手做。
- **規則改版不溯及已凍結的片**:已凍結的片照凍結時的稿做完,下一支才套新規則。
- **進度板** `channel\board.md`(`board.py` 產生,不手改):問「哪幾支在做什麼」只讀這一檔;`python -X utf8 pipeline\board.py set <tag> --stage <階段> --next "<一句>" [--blocked "<等誰>"] [--publish YYYY-MM-DD]`。

## 2. 卡點與接手
- run 結束碼 3 = 卡點:看 `production.json` 的 `blocks` 最後一筆與 `output\<tag>\director_<ver>.log`,`--explain <段>` 對項目。
- `待開工提問` 補 brief;`待選後端`、`Colab 要使用者上傳` 走 §6;`要問使用者`:把 `projects\<tag>\ask_user.json` 整理成一則問使用者,回覆後主對話處理並清空,再 `run --from <段>`(v3 的 B 段 review 步:只剩「錯/關掉」與 revise 後仍在的「誇大/可疑/相反」才問,整批一次;清空後重跑只對改過的句小範圍審 + 事實專審,不重來);估片長不足問「補素材/併題/照發」,照發加 `brief --allow-short`;`用量上限` 等重置再跑,不換模型硬跑。
- **主對話接手**:同一處卡兩次、或卡點不在上列,主對話修該步(改檔、派 core-dev),`run --from <該段>` 接回。不放寬 gate、不動品管門檻、不靠 `--force`/`--skip-*` 過關,真要繞在回報明講。介入記 `director.py intervene`,回饋記 `director.py feedback`。
- **handoff** `projects\<tag>\handoff.md` 只寫 director 產物沒有的:公開後待辦、風險、跨對話結論。脈絡 >約 20 萬或同一問題修兩次沒好,更新 handoff、commit 再開新對話,新對話只讀 handoff。

## 3. 開工提問(A 開頭一則訊息問完,≤5 行)
- 選題會議留下的題每題 1 行(題、切角建議、最強反駁→回應);淘汰題各一句理由,不展開。
- 問:角度一句(主對話先給建議)、劇透範圍、使用者玩過沒或有沒有一句想講的話(選答)、發布日(預設次日該頻道檔次)。回「照建議」或沒意見就照建議做。
- 不問:聲音、片長、素材、版面、動畫、BGM、技術。先要原始網址;使用者給整理稿就要原始報導連結。
- 數字沒單位(「10-15」)確認秒或分。不把工作轉嫁給使用者(多跑指令、多做決定)。

## 4. 對話與模型
- 一支片一個對話、一支 director 程序,不再切段開對話。入口對話須 Opus 5.5 高(Fable 也可):開工第一步 `get_session self`,不符就在開工提問那則請使用者切,只這一次;回覆裡不寫模型建議。director 內各步模型由 `llm.py` 與代理定義決定。
- 對話不能改自己的 model/effort、中途不換模型;要更高判斷力派代理。超高/最大不用。

## 5. 派工與回合
- 一件事一個代理;上限約 25 次工具呼叫或 8 萬脈絡,到了開新代理。查證先列完待查清單一次派完,只查會寫進文案的說法,追問用同一個 researcher;矛盾或要判斷真偽交回主對話。
- 派工寫明要動的檔、要讀的 `pipeline\docs\` 節、驗收指令、回報上限;不讓代理讀 `pipeline\README.md`、`news_specs` 全檔或整個 `projects\<tag>\`;改程式才先讀 README。
- 代理不看圖、不貼 diff/log/整個 json;長工作背景跑,代理只做到可以開跑。

## 6. 機器與指令
- 單跑指令:`director.py run --dry-run` 列指令序列;工具規格在 `pipeline\docs\`,C0 與遠端細節 `docs\tts.md` §4.8。
- 文案格式見 `docs\build.md`;`@def anim:名稱=...` 同組只定義一次。
- Python 輸出中文用 `-X utf8`。ffmpeg 的 drawtext 會當掉,文字用 Pillow。無頭 Edge 用 PowerShell 呼叫。
- GPU 一律走 `gpu_lock`、背景跑;要插隊改 board 的 `--publish`,不繞過鎖。
- **遠端配音不自動選後端(使用者 2026-10-29 指定)**:`tts_dispatch.py <tag>` 看三後端狀態,問「配音要在 C、K 還是本機?建議 X(一句理由)」,等回覆。開工已指定的照指定;到時不可用要再問,不自行改道。
  - **Colab(要使用者)**:有 Claude in Chrome 與 Drive 連接器就由主對話上傳 zip 到 Drive `CV_colab\`(做法 `docs\tts.md` §4.8),沒有就請使用者拖進去。dispatch 印的訊息照貼,寫明「這一步一定要你按,不按 Colab 不會開始」;回路徑後 `--colab-done <tag> <zip>`。**60 分鐘沒回或發布剩不到 6 小時** → `--colab-cancel <tag>`,再問改 K 還是本機。
  - **Kaggle** 全自動,失敗看 `tmp\remote\<tag>\run.log`,修好重跑接上次進度。**本機**走 gpu_lock。Kaggle/Colab 帳號各只用使用者本人一個。
- 使用者聽過的讀音 `pron_memory.py add`,證據記 `ear`。

## 7. 多支片、兩頻道各一支、日更排程
- 入口先把每支寫進 board(tag、頻道、發布日、GPU),再選題。開工提問一則,每支 ≤3 行,「照建議」整則適用。
- 一支一個 director 程序,GPU 走 gpu_lock、順序依 board 發布日(同日先到先做),進度看 board。每頻道同時最多 1 支 A/B + 1 支 C–E,超過的 board 寫「排隊」。
- 同一事件兩頻道各做一支:只查證一次,facts 共用,角度照各頻道檔。
- 共用檔(`cosy_terms.json`、`say_terms.json`、`scorecard.md`、`cover_persona_log.jsonl`)只新增條目、改完立刻 commit;board 只經 `board.py`。
- **日更排程(目標,尚未啟用)**:排程任務每天跑入口 prompt,開工提問改為發建議、不等回覆,否決窗照舊。**啟用條件**:連續 6 支(兩頻道各 3)全程無人工介入且公開後 24h 無事實更正;之前把人工介入的點記進 handoff「風險」。

## 8. token 用量(只在檢討整個流程時用)
- 平時不講用量。檢討流程時：先用 get_usage 讀官方五小時/週 %,`python -X utf8 pipeline\video_cost.py --snap --h5 <%> --h5-reset <ISO> --week <%> --week-reset <ISO> [--fable <%>]` 記快照(快照越多換算越準),再看 `video_cost.py --all`(`channel\token_ledger.md`)與單片 `video_cost.py <tag>`;對使用者只講占週上限 %。
- 檢討時對照 `channel\PLAN_全流程優化_2026-11-05.md` §1 證據表與 §2 P9 指標:每支 `production.json` 的 `interventions` 條數(基準 5–20)、`blocks` 中 D 段素材類與 C 段三輪未清條數(目標 0)、`video_cost.py <tag>` 週 %(基準中位 3.5%,目標 ≤2.5%)、版數與重錄次數不增;ChannelB P7 試行看 7d。
- 片名對照 `channel\tag_names.json`;聊天室提到片一律「中文短名(tag)」,brief 會自動補新片名,不準就直接改檔。
