# 1_選題:選題情報、配比、片長、時段、數據判讀

討論下一支片、配比、檔次、看成效數字時讀。頻道檔優先。

## 1. 選題情報
- 討論選題前先跑 `python -X utf8 "<EXTERNAL_BACKEND>\Youtube AD\tools\intel_query.py" ensure-today`(非今天背景跑約 4–6 分鐘;結束碼 2 = 舊情報,告知後繼續)。
- 再讀 `<EXTERNAL_BACKEND>\Youtube AD\data\intel\out\latest\README_FOR_OPUS.md`;深查單一事件用 `pack <事件ID>`。
- `intel_query.py opportunities --slot main|c`:主題機會分 v2(試行),與 00_overview 舊排序分歧時兩個都看;不是點閱預測,權重待 `channel\成效分析.md` 累積 n≥20 再定。
- heat = 報導量對數 × 平台數,不代表觀眾需求;需求看競品 views/日與同題支數(`context.md` §2)。
- 改 §3、§5 要同步 `<EXTERNAL_BACKEND>/_shared/RULES.md` 並通知(主對話做)。

## 2. 槽位制
- 每日每頻道 1 支自製是節奏目標(§3 表);當天沒有過得了 §6 門檻的題,ChannelA併題或做常青題、ChannelB做機制考據(頻道檔),不做湊數的速報,也不為了湊支數放寬三道閘門。
- 同一事件第 2 支,只在有新進展且首支 48h 曝光 ≥ 自製片中位時做。
- 新客位(頻道檔有定義者每週必填 1 支):華語競品同期 ≥4 支在做的大作或事件;標題結論先講、不用圈內梗。
- 節奏可預期:固定檔次、不長期斷更。
- 單支非主場片失敗不改方向、不補救性連發主場片;非主場不連發、不整週換題。
- 非主場預期是主場的一半;擴圈只選老觀眾也會看的鄰近題。
- 擴展實驗(§3):頻道定位與形式不變、題材往外跨一步,標題用新觀眾認得的作品名;只跟 12:00 自製片比,7 日觀看達同時段 2 倍的題材升 18:00/21:00 再做。
- 爆款後 1–2 週內排一支同批觀眾會看的片;非主場爆款最多追 1 支同題。
- 連續 3 週自製片 7 日觀看中位低於頻道檔門檻 → 重排配比,不加支數。

## 3. 配比與檔次(片長唯一來源 `pipeline\gates\specs.py FORMATS`;本節是唯一可出現頻道名處)
| 格式 | 每週 | 檔次 |
|---|---|---|
| ChannelA 評論片(上市窗主場片同) | 每日 1(每週 6–7) | 18:00 |
| ChannelA 長篇(上市窗的劇情/歷史/系統整理;試行 2 支至 2026-11-30 檢討) | ≤1 | 18:00 |
| ChannelA/ChannelB 搬運 | 各 ≤2 | 12:00 |
| ChannelA/ChannelB 擴展實驗(鄰近題往外一步;試行至 2026-11-30 檢討) | 各 ≤2 | 12:00 |
| ChannelB 考據片 | 每日 1(每週 6–7) | 21:00 |
| ChannelB 長篇(常青系列:穿越能活嗎、大百科、系列史;試行 2 支至 2026-11-30 檢討) | ≤1(佔考據片名額) | 21:00 |
| ChannelC | 先穩定 2 | 見頻道檔 |
- 12:00 彈性檔不設片長。目標片長是選題門檻不是硬下限:論點夠多才達成,不夠就併題或往深補,不拉長句子。時段固定,累積 n≥20 支後由 `feedback_report.py` 再檢討。

## 4. 同題材與判語
- 同一事件 7 天內(含搬運)≤1 支;同一系列每週 ≤2 支;新進展才算新事件;頻道檔標明不套用者除外。**上市窗例外**:上市、公測、壓測、大更新前 7 天到後 14 天,同一遊戲可每日 1 支,每支要有新問題或新數據。使用者排片可破例,不自動擋,事後分析也不把同題連上當成效差的原因(熱門題連發是驗證過的做法)。
- 同一負面判語的 14 天上限見 4_交付發片 §3.3。

## 5. 發布時段
- 檔次照 §3 表;傍晚檔是慣例與觀眾在線高峰,不寫成演算法規則。
- 週幾只當弱偏好;發布時間照觀眾在線時段,不刻意延後。
- 發布時間由主對話用後端 schedule API 設,不問使用者。

## 6. 選題門檻
- ChannelA主場片先問三件,至少中兩件才做:①兩邊在吵嗎(留言會不會互嗆)②觀眾此刻要做什麼決定(買不買、回鍋嗎、預購嗎)③在不在上市窗內。都不中的題降為 12:00 彈性檔或併題。
- 先列論點清單判斷撐不撐得起頻道片長帶下限(§3):一塊 90–150 秒含 1–2 論點、約 4–5 塊;撐不起併題或換題;寫完照實交並告知片長。
- 定角度前先寫「玩家共識」;事實核對與玩家審見 2_文案「三道閘門」。
- 標題、封面、核心論點各做三查(反面證據、絕對值不只倍數、官方預告或理由),結果寫進 handoff。
- 查無出處的前提與動機推論不得當標題、封面或核心論點,正文照 2_文案 §1.1「不拆台」。
- 一次只往外跨一步;形式不變、題材換;標題開頭與封面放新觀眾認得的名字。
- 擴圈片連續 3 支 48h 曝光低於頻道基準一半 → 退回更近的題。

## 7. 搬運與系列化
- 搬運只當新客入口:只收頻道檔白名單、只做主場題、一律 12:00;同事件 7 天內已有自製片就不搬。
- 自製片連續 3 週達頻道檔門檻 → 搬運減量。
- 搬運爆款的置頂留言與說明欄,接對應的同題自製片。
- 系列用固定欄目名,下一集在片尾 20 秒畫面與置頂留言預告;標題不加欄目前綴。
- 4 週數字沒動就換手段,不加碼。

## 8. 數據判讀
- 看:48h 曝光(匯出只有 48h、7d、28d 窗口,2026-11-03 起不用 72h)、CTR、近期觀眾%、訂閱淨變化/千次;每週一看頻道 28 天新客%、訂閱者觀看時間%。曝光擴大時點閱率本來會降;曝光欄缺資料不宣稱「曝光被縮」。
- 自製片跟自製片比;Studio「平常範圍」含搬運與高峰,不當自製基準。
- 訂閱/千 = 觀眾想看下一支的訊號(觀看=題目熱、均看=本片留得住、訂閱=信任頻道會再給)。只跟同期比(stats.py 印發布 ≤90 天合計),不跟舊片終身值比:ChannelA 2026-08 起全頻道降到 0.1–0.2,舊片同期也 0.35。單片淨增 <5 人不比。歷史 3–7/千的是常青長片(神作解析、公司興衰史、世界觀大百科、穿越能活嗎、爭議完整來龍去脈,多 14–29 分鐘);5–13 分鐘時事反應近 0。長篇試行(§3)檢討時看訂/千是否高於同期評論片/考據片,觀看不得低於同期中位一半。
- 窗口用 f48、7 日或同週相對值,不用「前 2 日」;YouTube 改觀看計算前後的資料不直接比。
- `SUBSCRIBER` 是首頁動態,不是訂閱者;訂閱者占比看 `SUBSCRIBED_TO_UPLOADER_STATE`。
- **數據一律走 `pipeline\stats.py`,不自己開 own.db、不自己算窗口**(用法與 age 起算見 `pipeline\docs\stats.md`);要深挖才去 Youtube AD 前端。規劃新片前與檢討前的指令見 CLAUDE.md 指引表。
  - 計畫文件開頭寫明引用的資料時間;輸出標「⚠ 數據非當天」時註明哪些判斷依據舊數據,等不到當天數據不擋規劃。
- 引用倍數標明自製或搬運、片長與形式;搬運倍數不當自製題材唯一依據。
- 樣本少、片長與日期共線不能當因果;同組 n ≥ 8 才改規則,附數字與依據。`channel\成效分析.md` n<8 的格不可引用為結論,「候選假設」不是教訓。
- 回溫片(2026-11-03):開工 hook `[回溫]` 與 `channel\rebound.json` 每日自動列出(來源 Analytics 逐日 + Studio「最新活動」48h)。看流量來源判處置:搜尋 → 長尾需求,做同題自製新片;推薦 → 演算法在試,快做續題/更新片;外部 → 一次性,不追。搬運片回溫只取主題,不算我們的內容力;無來源資料時標「來源未知」不下結論。
- 禁用說法:「先給 1,000 人測試」「頻道分數或基礎額度」「停更 N 天降權」「頻道被貼標籤」;只能說「推薦依每位觀眾的觀看歷史」。

## 9. brief
- 開工資料寫 `brief.json`(0_流程 §1)。
- 必填欄:事件 ID;heat 與來源數(報導量,非事件大小);官方有無事前預告;同事件近 7 天已發幾支(含搬運);檔次;槽位。

## 10. 選題會議(使用者沒指定題時必做,指定題時只做第 3 步;細則 `channel\_archive\plans\PLAN_流程嚴謹化_2026-10-29.md` §1)
1. 收集:`python -X utf8 pipeline\topic_scout.py --channel <頻道>` → `tmp\scout_<頻道>_<日期>.md`。印「人設過期」先重寫人設檔再派 topic-critic。Studio 分頁後端未抓前用 Claude in Chrome `get_page_text` 讀兩頁存 `tmp\studio_<日期>.txt`(≤3 次、不截圖)。
2. 候選題 5–8,每題 3 行:題與切角;需求證據(數字);可比片 tag + 7d;風險一句。回推片(scout 標出)必列一題:續集 / 更新片 / 不做,附「為什麼被推」判斷。
3. 反駁:派一次 `topic-critic`(Opus),給 scout 檔、候選題、`channel\audience\<頻道>_personas.md`、`channel\成效分析.md`;三席(老觀眾、數據、新客)每題各一條最強反駁 + 判定做/改角度/不做 → `tmp\critic_<頻道>_<日期>.md`。
4. 裁決:主對話留 2–3 題;每題一行「最強反駁 → 回應」與一行「預失敗」寫進 brief 與 handoff「風險」;72h 回填對照。不可因反駁不方便就跳過;反駁有依據而回應沒有的題不做。
5. 多支片一次會議,每批 critic 只派一次。完成 = scout 檔、候選 ≥5、critic 檔、留下的題有回應與預失敗、回推片有處置(程式不擋,主對話自查)。
