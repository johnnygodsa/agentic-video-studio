## 1. 先選形式(寫文案時就決定,顏色最後才選)[技]
| 這句話要觀眾看懂的事 | 用 | 不要用 |
|---|---|---|
| 一個數字(金額、銷量、人數) | 數字卡 `num`:大數字 + 單位 + 一行比較基準(「前作 2,300 萬」「比去年少 27%」)[外:單獨一個數字觀眾不知道好壞] | 只有一條的長條圖 |
| 2–7 個對象比大小 | 橫條,數值大的在上;順序本身有意義(階段、名次)才照原序 [外] | 圓餅 |
| 年、季這種時間資料,7 點以內 | 直條 `cols`,時間由左到右 [外] | 橫條(現況的毛病:2022–2026 用橫向排行條) |
| 佔比,或佔比前後變化 | 100% 堆疊橫條 `share`,一個時間點一條,上下對齊 | 把 60/40、40/60 拆成四條分開的條 |
| 前後兩個數(漲價、砍價) | 數字卡寫「80 → 100 元」加差額,或兩條加差額標示 | 兩條沒有標差額的條 |
| 一段時間有多長 | `span` | 遊戲畫面墊底 |
| 事件先後(5 個節點以內) | `timeline` | 清單 |
| 幾個問題、名單(5 項以內) | `list` | 一張塞 6 項以上 |
| 兩方說法、新舊對照 | `versus` | 兩張分開的卡 |
| 因果、步驟(4 個以內) | `flow` | 清單 |
| 超過 7 類 | 拆兩張,或留前 5 名加「其他」[技][外:類別上限 7] | 加更多顏色 |

## 2. 版面與字 
- 直式(2026-10-22):原生畫面窗 1080x1080(成片 y 260–1340,字幕在窗外),文字安全框 x 80–940、y 40–1040,窗內下方不留字幕帶;橫式內容底緣 y ≤ 800(圖表繪圖區下緣 800,有出處 780)。 直式 13 型(含 list / num / versus / span / stamp / flow / timeline 與 kit)皆有 `:root.portrait` 版面(2026-10-22 計畫 #5c):單欄 / 上下兩格 / 縱向軸 / 節點向下,字級與安全框同上。
- 內容底緣 y ≤ 800 [使:字幕帶];左右離畫面邊 ≥ 96px [外:標題安全區 90%]。網頁渲染的渲染前檢查另擋(2026-10-22):任何元素左右離邊 <40px、離上緣 <24px、進字幕安全帶(`IMG_BOTTOM_KEEP` 以下)都算錯誤。
- **網頁渲染所有文字 ≥ 44px**(`tokens.css` `--fs-min`;模板放不下先自動分頁 / 縮字 / 換行,再不行寫 `problems`,渲染前檢查報錯);直式(1080x1920)同樣 ≥ 44px,左右離邊 ≥ 40px。
- 必讀的字 ≥ 56px(約等於字幕字級;手機直拿時整個畫面寬只有 390 點左右,56px 約等於 11 點)[判];出處、註記 ≥ 44px。
- 一個鏡頭一個焦點:同一時間只有一組東西在動、只有一處用強調色 [外][判]。
- 標題 ≤ 14 個全形字,寫「比的是什麼」加單位。逐步顯示的鏡頭標題不寫結論(會先爆雷),結論靠強調色與旁白;一次全出的鏡頭標題直接寫結論 [判;外部建議「標題寫結論」是針對靜態簡報]。
- 出處、估計值、未證實這類聲明放右下小字(`src` 欄位),不塞進標題、不加括號 [使 2026-10-13 免責聲明只放畫面]。
- 標題與內文不用半形標點;用全形,或改成空格、斷行 [判]。換行不可留一兩個字的殘行(用 `_wrap_balanced`)[判]。
- 深色底上的白字描邊 ≤ 2px;不用同色描邊假裝粗體(現況「9 款」糊掉)[判]。
- 數值:數字大、單位小(約 0.75 倍,單位不小於 44px);`%` 前不留空格;千分位加逗號;大數用「萬、億」[外:主數字最大、標籤次要]。
- 內容區塊整體置中(區塊內文字可靠左),標題與內容共用一條中軸 [判]。
- timeline 節點說明 <= 8 個全形字,盡量不用英文長詞(節點間距只放得下約 5 個全形字一行,超過會換行、擠到相鄰說明)[判]。

## 3. 顏色
- 全片一組色票,所有動畫類型共用,不各用各的(現況:標題紅線、長條藍、強調琥珀、清單紅點、時間軸每節點一色)[外:4–6 個色碼][判]。
- 一個鏡頭 = 白/灰 + 一個強調色;紅色只留給「負面、否定、警告」的語意(印章、✗),不拿來當裝飾 [外:強調太多等於沒強調][技:狀態色不挪作他用]。
- 強調做法:先把全部畫成中性色,再只給「這句話在講的那一個」上強調色 [外 Datawrapper 第一手]。
- 類別色只在「類別本身就是主角」時用(聯盟/部落);一個鏡頭最多 3 個色相,同一對象全片同色 [技]。
- 網頁渲染的系列色(2026-10-22,`templates\anim\tokens.css` 的 `--series-1..4`):藍 #4f9dff / 青綠 #2fd1b4 / 珊瑚 #ff8a6b(share 第 4 段紫 #b794f6),三個明顯不同色相,對底色 7.0 / 10.1 / 8.4:1,皆不是強調金與危險紅;單系列用藍;負值柱 #ff5a5f;bars / cols / line / share 共用,圖例色塊與線 / 條同色。舊灰藍 3 階已廢(兩條灰分不清)。tokens.css 是網頁動畫與 kit 的色票 / 字級 / 間距唯一來源(金 `--accent`、綠 `--pos`、紅 `--neg`、`--panel`、`--fs-min`),模板與小件不自寫色碼。
- 時間軸節點同色,只有轉折點或正在講的節點用強調色;不可每個節點一種顏色 [判]。
- 文字不用資料色,識別靠旁邊的色塊 [技](長條圖已做到)。
- 新增類別色要跑 `validate_palette.js --mode dark`(dataviz skill 內);文字對比 ≥ 4.5:1、圖形對底色 ≥ 3:1 [外 WCAG]。已驗:聯盟藍 #2F6FD6 / 部落紅 #C8322B 全過。
- 深色底避免大面積高飽和色塊 [外:歐盟、Wear OS;另有一則廠商文章說可提高飽和度,來源較弱]。

## 4. 長條圖
- 基線從 0,不截斷 [外 Datawrapper、Urban 第一手];無格線、無數值軸,數值直接標在條尾 [外 Urban][已做]。
- 最多 7 條 [已做];3–8 秒的鏡頭建議 5 條以內 [判]。
- 條厚 56、條間 44,條間不小於 36 [使 2026-10-11]。外部建議條厚約為間隔的 2 倍 [外 Urban],現況 1.27 倍;使用者抱怨過條黏在一起,維持現況不加粗。
- 強調哪一條由文案指定(`hi`),指這句話的重點,不是自動挑最大值 [判];非強調條用中性色。
- 逐步顯示時比例尺固定用全部條的最大值,中途不重新縮放 [外 Heer & Robertson][已做]。
- 兩個維度要分組、組間留明顯間隔加組標題 [使 2026-10-09][已做]。
- 網頁版升級(2026-10-22,細節與 JSON 範例見 `docs\anim.md` §6):`series`(2–3 系列,出圖例,色用 §3 系列色)、`stack`(堆疊,段內放得下標數字、總和標末端,不可有負值)、`ref`(目標線 / 門檻,`{value,label}`,value 納入比例尺)、負值(以 0 為中線,負值紅色)、bars 最多 10 條 [判:網頁版不受 pillow 版 7 條版面限制,但類別 >7 仍建議拆圖]、標籤過長先縮字再換行。圖表繪圖區下緣離字幕安全線空白 >160px 時,模板自動把繪圖區拉高(版面調整,不報錯)。
- 軸暴衝(2026-11-05,`bars` / `cols` 的 `shock`,細節見 `docs\anim.md` §6「bars·cols 軸暴衝」):某一項遠大於其他項(>= 2 倍)時,先照舊比例尺長、暴衝項衝出框、座標軸重縮放,暴衝項金色定格——用於「這一項爆表」的敘事;不是每張長條圖都開,一般排行用預設。[判;外部參考 video-shotcraft axis-rescale-shock]
- 新圖表:`line` 折線 / 面積(≤3 條、標註點、時間比例 x 軸)、`table` 比較矩陣(≤5 列 × ≤4 欄)、`kpi`(2–4 格大數字並排),用法同 §1 形式選擇原則:趨勢用 line、規格 / 有無比較用 table、並列的幾個數字用 kpi。

## 5. 動作
- 每個元素進場 ≤ 0.8 秒;同類元素用同一組時長與曲線 [外 HyperFrames motion doctrine,第三方鏡像]。現況條生長 0.5 秒、ease-out,合格。
- 進場用 ease-out;**2026-10-22 使用者放寬([使] 計畫 §9):允許 ease-back 彈入**(back 1.4–1.7,用於節點、徽章、關鍵字、印章、數值標籤等,不限小東西),彈入後回正即靜止。仍禁循環彈跳、elastic 多次擺盪。
- 一步一句,分段出現;不可多處同時變化 [外:分段轉場多數情況較好;多處同時變化觀眾不知道看哪][使:每步在句首出現]。
- 到位後就靜止,**唯一例外(2026-10-22 使用者放寬)**:輕微浮動 ±3px、週期 ≥ 2 秒(箭頭尾端、「?」標記這類小件;不可循環彈跳、不可大幅位移);不做呼吸縮放、發光脈動。持續在動的主要是星座背景 [外][使:星座背景是使用者選定]。
- 數字跳動(count-up)**2026-10-22 起放寬為允許**:數字卡、`span`、`kpi`、徽章 `badge`、折線末點數字、長條 / 直條數值都可 count-up,一次、≤ 1 秒、停在終值(終值必須等於查證檔的數字,見本節下文);同一鏡頭只讓當前焦點的數字跳 [使 2026-10-22]。
- 最後一步完全顯示後停 ≥ 1.5 秒 [使]。
- 全片進場方式固定 2–3 種並重複使用,不要每種鏡頭發明一種 [外]。
- 資料鏡頭的時序分三段:待機(只有標題與空軸)→ 揭示 → 定格;一個資料鏡頭只講一個發現 [外 opus55video.dev 的 Animated data story 範本]。
- 畫面上的終值必須等於查證檔的數字;動畫程式不可用亂數、不可自己補數字 [外 同上][與查證規則一致]。
- 畫面上的字要短到在它停留的時間內讀得完(約每秒 6–7 個字,扣掉進場時間)[外 同上;秒數換算是判]。

## 6. 禁用清單(指名要避開的樣式;Opus 5.5 官方文件:籠統說「不要像 AI」沒用,要列出具體樣式,看了成品再補)
2026-10-22 依使用者決定([使] 計畫 §9)放寬 §5 後,**仍然禁用**:光暈(glow / drop-shadow 當發光)、霓虹、循環彈跳(bounce / elastic 重複)。允許:ease-back 彈入一次、count-up、±3px 且週期 ≥ 2 秒的輕微浮動。
- 每個項目或節點各一種顏色;彩虹色階。
- 漸層裝飾、光暈、玻璃質感面板、長條加陰影或立體。
- 大數字 + 小標 + 一排輔助數據 + 漸層的制式卡片(官方點名的預設樣式):數字卡只放一個數字和一行比較。
- 每個面板都是同一種細白框圓角(現況 `versus`、`flow`):改填色面板,不描框。
- 每個元素都是淡入加上滑。
- 截斷基線、雙軸、比接近數值的圓餅、只有一條的長條圖。
- 每個資料點都標數字的折線圖(長條直接標值不在此限)。

## 6b. 動態小件 kit(2026-10-22,計畫 #4;規格與欄位見 `docs\anim.md` §7,程式 `pipeline\kit.py` + `templates\kit\kit.html`)
疊在截圖、影片、閱讀卡、引言卡與網頁圖表鏡頭上的重點標示:callout / arrow / zoom / spotlight / pop / badge / lower / tick / cross / progress / punch。script.txt 行尾 json 的 `kit:[…]`。
- **節制規則 [判;使用者看過不行就改]**:同一句 ≤ 2 個(punch 也算)、同一鏡頭 ≤ 4 個(自動 lower 不計)、punch 每句 ≤ 1、spotlight 不用於 tilt 鏡頭。lint 先報、`build.py` 渲染前檢查再擋一次(錯誤)。一個鏡頭仍是一個焦點(§2):小件是指向焦點,不是多放幾個焦點。
- 動態只用 ease-out / ease-back / 筆畫畫出 / count-up;浮動 ±3px 週期 ≥ 2 秒;不用光暈、霓虹(線條下墊 55% 深色描邊讓線條在亮底可讀,不是光暈)、循環彈跳。顏色只用 tokens(金強調、綠 / 紅只表正 / 負語意)。
- **擺放避讓摘要**(`kit.layout`):自由擺放的小件(arrow / pop / lower / badge)不蓋住該鏡頭的文字框、圖表元素、字幕安全帶與其他小件;arrow 找箭尾離目標 120–260px 且箭身不碰障礙物的方向,pop 找最近空白處(必要時縮字最多 3 級),lower 預設左下字幕線上方,badge 目標外側右 > 上 > 左 > 下。放不下列警告。細節見 `docs\anim.md` §7「擺放規則」。
- **離邊**(2026-10-22,計畫 #5):小件圖層框在 push 推移(1.02 中心縮放)與 zoom / 漂移全程後離畫面邊仍須 ≥ 安全邊(左右 40px、上 24px);不足時該鏡頭的 push 自動減小(同 `_push_cap`)。

## 7. 檢查
- 程式量測(2026-10-22 起):動畫鏡頭以網頁模板實際排版量測(`anim_web.measure`:播到底取 `problems` 與全部元素外框),渲染前檢查(`build --check-only` / `make_version`)列錯誤:文字 <44px、元素超出安全區(左右 <40px、上 <24px、下進字幕安全帶)、標籤互相重疊;小件數量(同句 ≤2、同鏡頭 ≤4);kit 圖層離邊;錯誤 >0 不渲染。pillow 舊類型仍走 `build._check_src` 的底緣 ≤ 800 與左右 ≥ 96。
- 主對話看圖:每個動畫鏡頭的最後一格拼成 3 欄總覽,一格寬約 667px,等於模擬手機;這個大小看不清的字就是太小 [判]。
- 動態取三個時間點看:開場、動作途中、最後停留 [外 HyperFrames motion-graphics]。

## 8. 效率
- 2026-10-13 實測(三條長條、50 格):畫內容 6 毫秒/格,疊星座背景 108 毫秒/格。**星座背景佔自製動畫算圖時間約 95%**,Pillow 不是瓶頸,不必換繪圖函式庫。
- 星座 5 秒一循環(`STAR_LOOP`),30fps 只有 150 張不同的圖,算一次存起來重用。
- 已做(2026-10-13):`make_star_bg(t)` 整數格走快取(格索引 mod 150),磁碟 `build\_anim\star_v{STAR_VER}\NNN.png`(存最終背景 RGB 的無損 PNG,150 張共約 31MB;比存單通道浮點強度圖小很多,且輸出逐像素相同),同行程另有 LRU 記憶體快取(60 張約 373MB)。實測 50 格 bars 疊星座:改前 108 毫秒/格;冷快取(第一次,含算圖與寫檔)約 173 毫秒/格;熱快取(磁碟已有、新行程)約 20 毫秒/格;同行程第二次約 10 毫秒/格。`over_star` 只算 alpha > 0 的像素。鏡頭快取簽章用 `f0 % 150`,前面文案變動不會讓後面鏡頭重算。
- 外部查不到 Pillow、skia、cairo 的可用速度比較;HyperFrames 沒有官方速度數字,只有一則使用者經驗(本機 30 秒 1080p 約 3 分鐘,約 100 毫秒/格),不比現況快。
- HyperFrames 與 Windows(2026-10-13 查 GitHub issue,引文經小模型轉述,未逐字核對):官方沒有支援平台清單,維護者在 #5086 說 CLI 已可在 Windows 執行;Windows 上仍 open 的問題有磁碟空間檢查誤擋算圖(#4060)、防毒鎖檔 `spawn EBUSY`(#4058)、Smart App Control 擋 sharp 的 DLL(#4845)。這台機器有 Node 22.18,沒有 WSL 與 Docker。
- 規格上合用:`seekFrame(frame)` 同格同結果、可設 `data-fps`、有非 GSAP 的 adapter 介面;每秒 10 格的頓感要自己在 seek 裡把時間量化,且它預設會做靜止格去重(#3793),都未實測。
- 判斷:評論片的動畫不搬(現有畫圖只要 6 毫秒/格,搬過去不會更快);科普片要評估時只試 Windows 原生,拿一個場景算一次,跑不起來就放棄,不為它裝 WSL 或 Docker。
